# DT-004: Normalise Tables

**Status:** Planned  
**Date:** 2026-08-30  
**Phase:** 1 (Foundation → Production-Ready ETL)  
**Depends on:** DT-002 (Category Mapping Schema), DT-003 (Extract to GeoPackage)  
**Blocks:** DT-005 (Graph Construction), DT-010 (Search Index), DT-011 (Basemap)

---

## 1. Objective

Transform the 14 raw extracted layers from DT-003 into **6 normalised tables** that serve as the
authoritative spatial data foundation for routing, search, and rendering. Apply the controlled
category vocabulary to searchable units, deduplicate landmarks, derive vertical-order mappings for
cross-building floor alignment, and separate doors from architectural details for instruction hints.

---

## 2. Context

### 2.1 Inputs

- `build/wayfinding.gpkg` from DT-003 with 14 raw layers (7 native EPSG:26910 + 7 reprojected EPSG:4326)
- `packages/wayfinding/src/wayfinding/etl/category_mapping.yaml` (62 USE_TYPE → category rules)
- `packages/wayfinding/src/wayfinding/etl/schema.py` (Pydantic output schemas)
- [docs/01-data-findings.md](../01-data-findings.md) vertical_order table (§3), searchable units (§4), landmarks (§7)

### 2.2 Outputs

Six normalised tables written to `build/wayfinding.gpkg` **alongside the 14 raw layers from DT-003**.
The raw `Pathways_26910` and `Transitions_26910` layers remain intact for DT-005 graph construction.

**Storage model:** Each table is persisted as two GeoPackage feature layers (`<table>_26910` and
`<table>_wgs84`) due to dual-CRS requirements and GeoPackage's single-geometry-per-layer constraint
(see [ADR-0003](../adr/0003-normalised-etl-schema-and-dual-crs-storage.md)). **Final layer count after
DT-004:** 14 (raw) + 12 (normalised dual-CRS) = **26 layers**.

| Table | Rows | Purpose |
|---|---|---|
| `facility` | 3 | Building envelopes and codes (AQ, SH, ECC) |
| `level` | 11 | Floor plates with vertical_order for cross-building routing |
| `unit` | **1017** (exact) | Searchable destinations only (SEARCHABLE='Y'), with category + accessibility metadata + provenance |
| `landmark` | **40** (exact) | Deduplicated POIs (water fountains, vending machines) parsed from free-text DESCRIPTION; containerized GDAL query found exactly one same-category/same-level pair ≤0.5 m (FIDs 28 & 41 at 0.250728 m) |
| `detail` | **48728** | Walls, glazing, and other architectural linework for basemap (excludes doors) |
| `door` | **6865** | Door lines (USE_TYPE='ADO') split for instruction-hint generation |

**Total normalised records:** 56,664 (= 3+11+1017+40+48728+6865; down from 79,347 raw records in
_26910 layers due to searchability filter and deduplication).

### 2.4 Schema change: adding DoorSchema and accessibility provenance

DT-002 defined 7 schemas (Facility, Level, Unit, Landmark, Detail, Pathway, Transition) but did not
include a DoorSchema. Separating doors from details requires:

1. Adding `DoorSchema` to `schema.py` with fields: `door_id, use_type, level_id, geom_26910, geom_wgs84`
2. Updating `normalise_details()` to split ADO features into the `door` table
3. Detail table contains 48,728 non-door features; door table contains 6,865 ADO features

**Accessibility provenance fields:** Per
[.github/instructions/accessibility-claims.instructions.md](../../.github/instructions/accessibility-claims.instructions.md),
any field driving accessibility decisions must carry provenance. `UnitSchema` must be extended with:
- `verified_by: str | None` — provenance of accessibility claim (e.g., "source_gdb_use_type")
- `verified_date: str | None` — ISO 8601 date accessibility was verified

**Centroid method provenance field:** Per ADR-0003 §8, units with toxic geometries where ST_Centroid
returns null require an envelope-center fallback. Track the method used via:
- `centroid_method: str` — `'geometry_centroid'` (ST_Centroid succeeded) or
  `'envelope_center_fallback'` (envelope center used when ST_Centroid returned null)

For units where `accessible` is non-null (true OR false) and derived from `category_mapping.yaml`,
populate `verified_by="source_gdb_use_type"` and `verified_date="2026-08-29"` (stable source GDB date
from directory mtime 2026-08-29T01:44:22Z, NOT ETL run date, preserving idempotency and recording
source provenance). Both true and false values drive accessibility decisions (e.g., stairs are
explicitly inaccessible), so both require provenance.
For units where `accessible=null` (unknown), leave provenance fields null.

**ADR-0003:** [docs/adr/0003-normalised-etl-schema-and-dual-crs-storage.md](../adr/0003-normalised-etl-schema-and-dual-crs-storage.md)
defines the dual-CRS storage model (paired layers), accessibility provenance requirements, PK
derivation rules, clustering algorithm, centroid fallback for toxic geometries (§8), and landmark
temp-layer prohibition (§9). Door table addition is an ETL-internal change (no API surface change);
ADR-0003 covers the broader schema organization, not DoorSchema itself.

## 3. Acceptance Criteria

All criteria are deterministic, testable, and map 1:1 to test cases (see §5 Test List).

### AC1: facility table structure and content

- **3 rows**, one per building (AQ, SH, ECC)
- Columns: `facility_id` (string, PK), `code` (string, from NAME), `name` (string, from NAME_LONG),
  `geom_26910` (MultiPolygon Z), `geom_wgs84` (MultiPolygon)
- `facility_id` values match source `FACILITY_ID` exactly
- `code` values: "AQ", "SH", "ECC" (exact match to data findings §3)
- Geometries preserve source extents and CRS
- **Test:** `test_normalise_facility_count_and_schema`

### AC2: level table structure and vertical_order correctness

- **11 rows**, covering vertical_order range [-2, 3]
- Columns: `level_id` (string, PK), `facility_id` (string, FK to facility), `short_name` (string,
  from NAME_SHORT), `vertical_order` (integer), `geom_26910` (MultiPolygon Z), `geom_wgs84`
  (MultiPolygon)
- `vertical_order` values match [docs/01-data-findings.md §3 table](../01-data-findings.md#3-facilities-and-levels) exactly:
  - AQ: -2 (1000), -1 (2000), 0 (3000), 1 (4000), 2 (5000), 3 (6000)
  - SH: -1 (100), 0 (1000), 1 (2000), 2 (3000)
  - ECC: 0 (3000)
- Every `level_id` maps to exactly one `facility_id`
- **Tests:** `test_normalise_level_vertical_order`, `test_normalise_level_facility_mapping`

### AC3: unit table structure and searchability filter

- **1017 rows** (only features where source `SEARCHABLE='Y'`)
- Columns: `unit_id` (string, PK), `room_id` (string, nullable), `level_id` (string, FK to level),
  `use_type` (string), `category` (string), `accessible` (boolean, nullable), `gender` (string,
  nullable), `verified_by` (string, nullable), `verified_date` (string, nullable),
  `centroid_26910` (Point Z), `centroid_method` (string, required), plus ONE registered geometry
  column `geom` in EPSG:26910 (for unit_26910 layer) or EPSG:4326 (for unit_wgs84 layer)
- `room_id` populated for all rows (data findings §4: "100% populated")
- `use_type` preserved from source Units layer
- `centroid_26910` computed as ST_Centroid(geom) in EPSG:26910, or envelope center if ST_Centroid
  returns null (see ADR-0003 §8 for toxic geometry fallback)
- `centroid_method` populated for all rows: `'geometry_centroid'` when ST_Centroid succeeds,
  `'envelope_center_fallback'` when ST_Centroid returns null and envelope center is used
- `verified_by` and `verified_date` populated for all rows where `accessible` is non-null (true OR
  false; per ADR-0003, both true and false values drive accessibility decisions, e.g., stairs are
  explicitly inaccessible)
- **Test:** `test_normalise_unit_count_and_searchable_filter`

### AC4: unit category mapping and coverage

- Every row has `category` populated from `category_mapping.yaml` via `use_type` lookup
- No null `category` values (fail build if mapping is incomplete)
- `accessible`, `gender` metadata flags populated from mapping YAML where defined
- `verified_by="source_gdb_use_type"` and `verified_date="2026-08-29"` whenever `accessible` is
  true or false. Both values drive accessibility decisions, so both require provenance. When
  `accessible` is null (unknown), both provenance fields are null.
- Example mappings verified:
  - "Washroom, single-stall, accessible" → category='washroom', accessible=true, gender='neutral',
    verified_by='source_gdb_use_type', verified_date='2026-08-29'
  - "Office" → category='office', accessible=null, gender=null, verified_by=null, verified_date=null
  - "Stairs" → category='vertical_circulation', accessible=false, verified_by='source_gdb_use_type',
    verified_date='2026-08-29'
- **Tests:** `test_normalise_unit_category_coverage`, `test_normalise_unit_category_examples`

### AC4a: unit centroid method provenance

- Every row has `centroid_method` populated: `'geometry_centroid'` or `'envelope_center_fallback'`
- No null `centroid_method` values
- When `centroid_method='envelope_center_fallback'`, `centroid_26910` equals the envelope center:
  `(envelope.minX + envelope.maxX)/2, (envelope.minY + envelope.maxY)/2` in EPSG:26910
- Build logs a warning for each fallback case, listing `unit_id` and envelope bounds
- Example: `SFU_BURNABY_QUAD_2000_2017` (toxic geometry `GEOMETRYCOLLECTION()`) has
  `centroid_method='envelope_center_fallback'` and `centroid_26910=(506011.7248, 5458491.1155)`
- **Tests:** `test_normalise_unit_centroid_method_coverage`,
  `test_normalise_unit_centroid_fallback_toxic_geometry`

### AC5: landmark deduplication and category parsing

- **Exact row count: 40** (down from 41 source features; containerized GDAL pairwise query found
  exactly one same-category/same-level pair ≤0.5 m: FIDs 28 and 41 at 0.250728 m)
- Columns: `landmark_id` (string, PK), `category` (string), `level_id` (string, FK to level), plus
  ONE registered geometry column `geom` (Point Z for _26910, Point 2D for _wgs84)
- `category` parsed from `DESCRIPTION` field using regex: `^(Water Fountain|Vending Machine)`
  - "Water Fountain near AQ 6028C" → category='water_fountain'
  - "Vending Machine close to Room 2013.4" → category='vending_machine'
- Duplicates removed using **greedy first-point-wins** clustering (per ADR-0003): sort by
  `(category, level_id, X, Y)` ascending, for each point mark all others within 0.5 m as duplicates,
  keep first point per cluster
- `landmark_id` derived from source FID of representative point after deduplication, prefixed with
  `LMK_`. Landmarks_26910 layer has no GlobalID or DETAIL_ID field (verified in
  build/wayfinding.gpkg; fields are DESCRIPTION, LEVEL_ID, VERTICAL_ORDER, FID only).
- Data findings §7 mentions "Vending Machine close to B9201" appears 5× — confirm only 1 survives
- **Zero temp-layer metadata entries:** After normalisation completes, assert zero entries in
  `gpkg_contents` and `gpkg_geometry_columns` matching pattern `landmarks_parsed%`. All landmark
  processing must use in-memory structures; no persistent temp layers (per ADR-0003 §9).
- **Tests:** `test_normalise_landmark_deduplication`, `test_normalise_landmark_category_parsing`,
  `test_normalise_landmark_no_temp_layers`

### AC6: detail table structure and door exclusion

- **48728 rows** (55,593 source Details minus 6,865 ADO doors)
- Columns: `detail_id` (string, PK, preserves source DETAIL_ID field directly), `use_type` (string),
  `level_id` (string, FK to level), plus ONE registered geometry column `geom` (MultiLineString Z
  for _26910, MultiLineString 2D for _wgs84)
- All rows have `use_type IN ('AGL', 'AWA', 'AWAFU', 'AWAMO', 'AWACO')` — no 'ADO'
- Expected counts by use_type (from data findings §6):
  - AGL (glazing): 32,974
  - AWA (wall): 11,002
  - AWAFU: 4,547
  - AWAMO: 196
  - AWACO: 9
- **Test:** `test_normalise_detail_door_exclusion`

### AC7: door table structure and ADO extraction

- **6865 rows** (all source Details with USE_TYPE='ADO')
- Columns: `door_id` (string, PK, preserves source DETAIL_ID field directly), `use_type` (string,
  always 'ADO'), `level_id` (string, FK to level), plus ONE registered geometry column `geom`
  (MultiLineString Z for _26910, MultiLineString 2D for _wgs84)
- Every row has `use_type='ADO'`
- Geometries preserved exactly from source Details layer
- **Test:** `test_normalise_door_extraction`

### AC8: vertical_order invariant across units and levels

- Every `unit.level_id` resolves to exactly one `level.vertical_order`
- Every `(facility_id, vertical_order)` pair in the level table is unique
- **Test:** `test_normalise_vertical_order_invariant`

### AC9: geometry and CRS correctness

- All `_26910` geometries are EPSG:26910, dimensionality preserved from source (3D for native layers)
- All `_wgs84` geometries are EPSG:4326, 2D (Z dropped for web compatibility)
- Bounding boxes match source extents (505981–506254 E, 5458380–5458560 N in EPSG:26910)
- **Test:** `test_normalise_geometry_crs`

### AC10: deterministic and idempotent execution

- Unit `accessible` flag is populated only from category_mapping.yaml; never inferred from other fields

- Unknown defaults to `accessible=null`, never `true`
- No path-level or door-level accessibility data exists (gaps G1–G3); fields reflect **destination
  accessibility only**, not route accessibility
- Follows [.github/instructions/accessibility-claims.instructions.md](../../.github/instructions/accessibility-claims.instructions.md)
- **Test:** `test_normalise_accessibility_provenance` (asserts accessible field matches YAML,
  verified_by/verified_date populated correctly for all non-null accessible values, no fabricated
 ons.md](../../.github/instructions/accessibility-claims.instructions.md)
- **Test:** `test_normalise_accessibility_provenance` (asserts accessible field matches YAML,
  verified_by/verified_date populated correctly, no fabricated values)

### AC12: container execution only

- All normalisation logic runs inside the ETL container (no host Python/GDAL)

- Follows [.github/instructions/container-only-execution.instructions.md](../../.github/instructions/container-only-execution.instructions.md)

## 6. Implementation Steps

Sized to half-day increments for progress tracking.

### Step 1: Add DoorSchema and update schema.py (0.5 day)

- Add `DoorSchema` class to `packages/wayfinding/src/wayfinding/etl/schema.py`
- Fields: `door_id, use_type, level_id, geom_26910, geom_wgs84` (mirrors DetailSchema)
- Update module docstring to list 8 schemas (was 7)

### Step 2: Implement normalise_facilities() (0.5 day)

- Read `Facilities_26910` and `Facilities_wgs84` layers
- Map `FACILITY_ID → facility_id`, `NAME → code`, `NAME_LONG → name`
- Write 3 rows to `facility` table using ogr2ogr or Python GDAL
- Tests 3–5 pass

### Step 3: Implement normalise_levels() (0.5 day)

- Read `Levels_26910` and `Levels_wgs84` layers
- Map `LEVEL_ID → level_id`, `FACILITY_ID → facility_id`, `NAME_SHORT → short_name`, `VERTICAL_ORDER → vertical_order`
- Write 11 rows to `level` table
- Tests 6–8 pass

### Step 4: Implement normalise_units() with category mapping and centroid fallback (1.5 days)

- Load `category_mapping.yaml` into dict
- Read `Units_26910` and `Units_wgs84` layers
- Filter WHERE `SEARCHABLE='Y'` (1017 rows)
- For each unit:
  - Map `UNIT_ID → unit_id`, `ROOM_ID → room_id`, `LEVEL_ID → level_id`, `USE_TYPE → use_type`
  - Lookup `use_type` in category_mapping.yaml → populate `category`, `accessible`, `gender`
  - If `accessible` is non-null (true OR false), populate `verified_by="source_gdb_use_type"` and
    `verified_date="2026-08-29"` (stable source GDB date, per ADR-0003)
  - If `accessible=null`, leave `verified_by` and `verified_date` as null
  - Fail build if use_type not in YAML (missing mapping)
  - Compute `centroid_26910 = ST_Centroid(geom_26910)`
  - If ST_Centroid returns null (toxic geometry), use envelope center fallback:
    `centroid_26910 = ((env.minX + env.maxX)/2, (env.minY + env.maxY)/2)` and log warning with
    unit_id and envelope bounds
  - Populate `centroid_method` field: `'geometry_centroid'` if ST_Centroid succeeded,
    `'envelope_center_fallback'` if fallback was used (ADR-0003 §8)
- Write 1017 rows to `unit_26910` and `unit_wgs84` layers (dual CRS, per ADR-0003)
- Tests 9–16 pass (includes new centroid tests 15–16)

### Step 5: Implement normalise_landmarks() with deduplication (in-memory only) (1 day)

- Read `Landmarks_26910` and `Landmarks_wgs84` layers **into memory** (GeoPandas or Python list)
- Parse category from DESCRIPTION using regex: `^(Water Fountain|Vending Machine)` → 'water_fountain' | 'vending_machine'
- Sort points by `(category, level_id, X, Y)` ascending (ADR-0003: greedy first-point-wins)
- For each point, mark all others within 0.5 m (Euclidean in EPSG:26910) as duplicates; keep first
- Derive `landmark_id` from source FID of representative point, prefix `LMK_` (no GlobalID or
  DETAIL_ID field exists; verified in build/wayfinding.gpkg)
- **Do NOT create any temp GeoPackage layers** (e.g., `landmarks_parsed_26910`) — use only in-memory
  structures (ADR-0003 §9)
- Write exactly 40 rows to `landmark_26910` and `landmark_wgs84` layers (41 source - 1 duplicate)
- Tests 17–20 pass (includes new temp-layer test 20)

### Step 6: Implement normalise_details() and door split (1 day)

- Read `Details_26910` and `Details_wgs84` layers (once, 55,593 features)

## 7. Error Handling

All errors are deterministic, fail-fast, and produce actionable messages:

| Error Condition | Handling | Exit Code |
|---|---|---|
| Missing category_mapping.yaml | RuntimeError with path hint | 1 |
| USE_TYPE not in category mapping | RuntimeError listing missing types; must update YAML | 1 |
| Searchable unit count ≠ 1017 | Warning logged (data change); does not fail build | 0 |
| ST_Centroid returns null (toxic geometry) | Warning logged with unit_id and envelope bounds; envelope-center fallback applied (ADR-0003 §8) | 0 |
| Landmark DESCRIPTION parse failure | Warning logged; landmark excluded from output | 0 |
| Temp GeoPackage layers persist after normalise_landmarks | RuntimeError; test fails (test_normalise_landmark_no_temp_layers); must not write temp layers | 1 |
| Missing level_id in child table | RuntimeError with FK violation details | 1 |
| Geometry CRS mismatch | RuntimeError with layer and expected CRS | 1 |
| GeoPackage layer missing | FileNotFoundError with layer name | 1 |

## 8. Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| **R1: Category mapping incomplete** — a new USE_TYPE appears in production data | Build fails; no fallback category | Fail-fast design surfaces the issue immediately; add missing mapping to YAML and rerun ETL |
| **R2: Landmark deduplication too aggressive** — important landmarks merged | Users cannot search for specific POI | Test with known duplicates (B9201 vending machine); tune 0.5 m threshold; validate 40 output count (exact, based on containerized GDAL pairwise query finding exactly one duplicate pair) |
| **R3: Searchable unit count changes** — source GDB updated (e.g., to 1020 searchable units) | Acceptance test fails (hard failure for this pinned source) | Update AC3 to new exact count and document source version change; do NOT use ±5 tolerance — drift signals source version update |
| **R4: Door split breaks basemap rendering** — downstream code expects doors in detail table | Map tiles missing doors | DT-011 must query both detail and door tables; validate in basemap test |
| **R5: Vertical_order mapping breaks** — facility adds new level with non-contiguous vertical_order | Graph construction fails | Validation in AC8 catches this; no assumption of contiguous vertical_order in code |
| **R6: Envelope-center fallback places centroid outside concave unit** — toxic geometry fallback may yield geometrically invalid centroid (outside unit boundary) for concave polygons | Graph snapping connects to wrong pathway; routing delivers user to incorrect location | Build logs all fallback cases with unit_id and envelope bounds; DT-009 QA visually inspects each (1/1017 in current data = manual review feasible); if invalid, flag for source geometry correction or manual centroid override |
| **R7: Temp landmark layers pollute GeoPackage metadata** — implementation uses physical temp layers instead of in-memory processing | QGIS warnings, phantom layers in ogrinfo, non-idempotent builds | Regression test `test_normalise_landmark_no_temp_layers` fails; must rewrite to use in-memory structures (per ADR-0003 §9) |
