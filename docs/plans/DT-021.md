# DT-021 — Usable route framing and map zoom

Status: implemented and verified; see `../reports/DT-021.md`.

The user supplied AQ303 → AQ3149, showing a successful route but a map tightly
framed around its starting marker. Browser page zoom does not change the SVG
camera. Current step selection always sets `mapFit=step`; the departure step has
only a point, producing a 16 m square view of a roughly 224 m route.

Open a new route with its current-floor route visible. Preserve selected-step
highlighting, but keep point-only departure/arrival/transition steps in useful
route context. Provide explicit accessible map zoom controls and reliable route
and floor reset actions. Manual camera state must survive same-floor redraws;
changing floors must establish a valid new frame. Do not modify route geometry,
backend algorithms, sources or accepted artifacts.

Implement focused client regressions after demonstrating the initial framing
failure. Extend real Docker browser E2E with the exact supplied room pair: initial
route extents visible, zoom-out expands the SVG camera, zoom-in reverses it, reset
restores the route, step selection still highlights exact geometry, and desktop
and mobile remain usable. Preserve existing canonical routes, floor transitions,
stale-response tests and 320px coverage. Run relevant gates and independent
large-model review before acceptance, then record screenshots and handoff.
