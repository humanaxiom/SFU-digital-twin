# DT-014: Bounded Indoor X-to-Y PoC

**Status:** Planned — urgent stakeholder slice
**Date:** 2026-09-10
**Phase:** Cross-phase stakeholder demo
**Depends on:** DT-003 through DT-007, DT-013, ADR-0008
**ADR:** ADR-0008

## Objective

Extend the artifact-backed DT-013 demo with honest deterministic indoor directions between exact
rooms today. Route only over the measured contracted graph, bind rooms to disclosed approximate
same-level pathway anchors, and fail explicitly when endpoints are unavailable or disconnected.

## Inputs and exclusions

- `build/wayfinding.gpkg`, mounted read-only by the demo.
- `build/graph_contracted.pkl`, mounted read-only by the demo.
- `build/graph_contracted_stats.json`, mounted read-only by the demo.

The three geodatabases under `data/` remain immutable and are not mounted by the demo. Revised
pathway profiling/rebuild and supplemental entrance/door/ramp profiling move to the follow-up
evidence ticket described in ADR-0008. No outdoor network, public map geometry, or public tiles are
inputs.

## Acceptance Criteria

1. Startup fails closed unless the GeoPackage and contracted-graph hashes match the lineage values
   in `graph_contracted_stats.json`; no artifact is modified.
2. An immutable endpoint catalog deterministically maps each eligible searchable unit centroid to
   the nearest contracted graph node on the exact same `level_id`, with lexicographic tie-breaking.
3. Endpoint attachment distance is measured in EPSG:26910 and must be at most 10 m. Missing,
   cross-level, and over-limit attachments return `422 endpoint_unavailable`.
4. Endpoint anchors are not graph edges, carry no walkable geometry, add no route distance, and are
   always disclosed as approximate; both attachment distances are returned.
5. `POST /demo/v1/route` accepts exact unit IDs and a required `default` or `elevator_only` profile.
6. `default` permits pathway, stairs, and elevator edges. `elevator_only` permits pathway and
   elevator edges only. No request silently changes profile.
7. Profile-specific component IDs are computed deterministically. A mismatch is detected before
   shortest-path execution and returns `409 disconnected` or `409 no_elevator_only_route`.
8. Successful routes minimize `length_3d` with deterministic equal-cost tie-breaking and return
   graph-only distance, per-level EPSG:26910 LineStrings, and deterministic steps derived from route
   geometry and transition attributes.
9. Every traversed edge is revalidated against the selected profile. An elevator-only result can
   contain no stairs edge.
10. Route success and failure envelopes include exact GeoPackage, graph, and stats hashes, source
    status, algorithm version, profile, endpoint details, and warnings.
11. Every elevator-only result says elevators only and stairs excluded, and lists `door_width`,
    `path_width`, `slope`, `powered_doors`, and `surface` as unverified.
12. Closures, opening hours, door access, elevator status, and room-to-anchor traversal are visibly
    unverified. No wheelchair-certified, campus-wide, or guaranteed step-free claim appears.
13. The deterministic assistant supports exact “directions from X to Y” by delegating to the same
    route service. Mobility phrasing forces `elevator_only`; ambiguity and failures pass through.
14. The existing SVG explorer adds exact origin/destination selection, a two-profile control, route
    overlay, synchronized per-level steps, attachment disclosure, and an explicit disconnected
    state on desktop and mobile.
15. The demo remains loopback-only, container-only, artifact-only, and offline. It adds no FastAPI,
    MapLibre, PMTiles, FTS5, LLM, nearest search, travel-time estimate, outdoor routing, or public
    map dependency.
16. Data QA identifies checked-in representative successful and disconnected room pairs for both
    profiles; tests do not assume arbitrary room pairs are connected.

## RED Tests

- Startup artifact presence, exact hash match, read-only mounts, and graph deserialization failure.
- Endpoint catalog same-level selection, 10 m rejection, tie-breaking, determinism, and no graph
    mutation or connector geometry.
- Exact endpoint resolution, ambiguous/unknown identifiers, same-room route, and bounded input.
- Profile edge filters, stable component IDs, precheck-before-search, disconnected envelopes, and
    prohibited-mode rejection.
- Deterministic shortest paths, graph-only distances, per-level geometry, transition steps, and
    repeated-response equality.
- Elevator-only no-stairs property tests and complete accessibility disclosures on success/failure.
- Assistant route delegation, ordinary default profile, mobility override, ambiguity, and verbatim
    no-route behavior.
- Static-client controls, route/failure rendering, floor synchronization, keyboard operation,
    provenance, limitations, responsive layout, and absence of external assets.
- Existing DT-013 lookup, security, and deployment tests remain passing after route refusal is
    replaced by the ADR-0008 capability contract.

## Architecture and Rollback

ADR-0008 controls this ticket. It selects the measured legacy artifact set for the PoC, defines
non-traversal room anchors, adds the `/demo/v1/route` component boundary, and keeps revised-source
promotion independent and evidence-gated.

Rollback removes the route module, route endpoint, assistant route intent, and route UI while
restoring DT-013's explicit route refusal. Approved artifacts and all source geodatabases remain
untouched.

## Deferred revised-source evidence

The previous DT-014 scope becomes the immediate follow-up ticket. It must profile all three local
geodatabases read-only; rebuild revised artifacts under an isolated output root; reconcile pathway
IDs and EPSG:26910 geometry hashes; measure default/elevator-only component and searchable-unit-pair
reachability; keep supplemental entrance/door/ramp layers profile-only; and perform opt-in,
non-geometric Room Finder identity reconciliation. No revised artifact becomes canonical without a
source-promotion ADR and complete lineage evidence.
