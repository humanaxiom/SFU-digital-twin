# DT-016 — Source review and isolated baseline rebuild

Status: implemented and locally verified. Started 2026-09-11. Decision: ADR-0011.
Published-image certification remains open; no production or source promotion approval.

## Outcome

Turn the local source findings into executable evidence and replace the no-op
`make etl` with a safe, complete legacy rebuild. Every run writes a new directory
under `build/experiments/`; accepted artifacts and running demos remain unchanged.

This work can proceed independently of GHCR access, CI activation and physical
LAN acceptance. Those remain delivery requirements, not dependencies of local
source analysis or isolated construction.

## Ordered scope

1. Compare all seven indoor layers from the legacy and revised source snapshots,
   mapping the renamed pathway layer explicitly. Record directory hashes, schema,
   CRS and per-FID content changes, plus per-feature reasons preventing ingestion.
   Inventory supplemental layers without ingesting them. Never infer missing
   facility/floor identity from geometry, Z or vertical order.
2. Extract the verified legacy snapshot into a new run directory. Refuse run reuse,
   path escapes, symlinks and source drift. Keep the raw extracted GeoPackage.
3. In an artifact-only container, copy the raw extraction and run normalization,
   raw graph, transitions and contraction. Record inputs when consumed, durable
   output hashes and an explicit stage chain. Use existing legacy semantics.
4. Finalize in a source-capable container only after all artifact hashes, stage
   prerequisites, code/toolchain identity and the source hash still match.
5. Compare two independently built legacy candidates using complete canonical
   graph content, unit/anchor identities and profile-specific room reachability.
   Distinguish byte identity from semantic reproducibility.

Revised graph construction is deferred until its 141 unassigned pathways are
reconciled. A build that silently removes them is not a revised-source result.
Supplemental ingestion and promotion require their own accepted decisions.

## Acceptance

- RED/GREEN synthetic tests exercise source additions/removals/changes, renamed
  layers, invalid identities and geometry, deterministic ordering, output refusal,
  stage failure/tampering and semantic differences including parallel/directed edges.
- Source review reports all three facilities, the preserved 22,426 legacy pathways
  and 141 revised additions, with explicit ingestion blockers.
- Two complete isolated legacy builds use separate run IDs, succeed through source
  finalization, and have equal canonical semantics. Reports include actual image ID,
  relevant code identity, source hash, stage inputs/outputs and exact limitations.
- Fresh source/artifact containers enforce read-only inputs, hidden workspace data,
  separate source capabilities and isolated writable outputs; no package installation.
- Full test/coverage, lint, type and artifact-QA gates pass with exact skips recorded.
  Before declaring green, rerun the complete Docker source-to-candidate workflow
  and the real demo browser/API gate on the final runnable state; historical
  browser evidence and unit tests alone do not satisfy end-to-end acceptance.
  Independent large-model review covers final implementation and evidence.
- Handoff, README and changelog identify the next actionable reconciliation work.

## Delegation

The large-model lead owns plan, stage orchestration, output safety and integration.
Independent large-model workers own source comparison and semantic comparison with
their tests. A smaller worker implements the bounded Compose/PowerShell adapter.
Review crosses implementation ownership; workers do not approve their own changes.

## Follow-up

Local acceptance evidence: final candidates C/D completed and compared equal in graph,
unit, anchor and profile reachability semantics. Source review preserves all seven
legacy layers and reports the 141 additions plus eleven multipart-ordering issues.
Final Docker suite: 535 passed, 16 skipped, 86.01% coverage; lint, types, artifact QA
and launcher gates passed. See [execution evidence](../reports/DT-016.md).

Integration found eleven legacy AQ3000 pathways with noncontiguous stored part
order, although their parts form connected chains when reordered. The existing
legacy builder flattens their stored order. DT-016 reproduces that legacy behavior
and reports the defect; completing a build is not a source-quality approval.

[DT-017](DT-017.md) should first reconcile multipart graph construction, then
establish authoritative facility/level assignments or a separately
specified outdoor-network model for the 141 additions, then build revised artifacts
in isolation and measure gained/lost room-pair reachability. DT-009's production
lineage/promotion contract is informed by this experiment but is not automatically
completed by it. Source files are immutable throughout.
