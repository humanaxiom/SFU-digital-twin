# DT-001: Harness Bootstrap — Containerized Test Execution Model and Package Skeleton

Status: planned
Date: 2026-08-29

## Problem statement

Phase 0 (data findings, system design, harness scaffolding) is complete, but nothing under
`packages/` or `infra/` exists yet. Before any ETL, routing, or API work can start (Phase 1+), we
need the reproducible, container-only test/lint/type execution model and the minimal Python package
skeleton that all future tickets will build on.

Without this bootstrap, there is no gate to run, no place for product code to live, and no way to
enforce the "no local Python/GDAL ever" constraint from `.github/instructions/container-only-execution.instructions.md`.

## Scope

Establish the foundation only — no product logic. This ticket produces:

1. An ADR (0002) documenting package layout, coverage floors, and the container execution model.
2. `packages/wayfinding/` skeleton with `pyproject.toml`, empty `src/`, and `tests/`.
3. `infra/docker-compose.yml` defining a `test` service that mounts the package `:rw` and the
   source GDB `:ro`.
4. `Makefile` wrapping `docker compose run --rm test <target>` for `make test`, `make lint`,
   `make type`.
5. One smoke test (e.g. `tests/test_smoke.py::test_imports`) that passes, demonstrating the gate
   works end-to-end.

**Non-goals (deferred to Phase 1+ tickets):**

- ETL implementation (graph construction, GeoPackage export, FTS index build).
- Routing engine, API, search, or assistant.
- Web client, basemap generation, or PMTiles serving.
- CI configuration (Phase 4+) — this ticket establishes the *local* gate only; CI will later invoke
  the same `make` targets.

## Implementation steps

Each step sized to ≤ 0.5 day. Do not start until `architect` writes ADR-0002.

### Step 1: ADR-0002 (architect only)
- Write `docs/adr/0002-package-layout-and-container-execution.md` covering:
  - Package layout: `packages/<name>/src/<name>/`, `pyproject.toml` per package.
  - Per-package coverage floors (not one blended number): initial floor 85% line for
    `packages/wayfinding`.
  - Container execution model: every gate target wraps `docker compose run --rm test <cmd>`.
  - Source GDB mount `:ro` at `/data/IndoorWayfinding.gdb` in all services.
  - Tool choices: `ruff` for lint, `pyright` or `mypy` for type, `pytest` + `pytest-cov` for tests.
- Duration: 2 hours (reading reference, writing decision, consequences, migration path).

### Step 2: Package skeleton (implementer)
- Create `packages/wayfinding/pyproject.toml` with:
  - `[project]` metadata: name `wayfinding`, version `0.1.0`, requires-python `>=3.12`.
  - Dependencies: `fiona`, `shapely`, `networkx`, `pytest`, `pytest-cov`, `ruff`, `pyright`.
  - Tool config: `[tool.pytest.ini_options]`, `[tool.ruff]`, `[tool.pyright]`.
- Create `packages/wayfinding/src/wayfinding/__init__.py` (empty for now).
- Create `packages/wayfinding/tests/test_smoke.py` with `test_imports()` that imports `wayfinding`.
- Duration: 1 hour.

### Step 3: Docker Compose service (implementer)
- Create `infra/docker-compose.yml` with a `test` service:
  - Image: `ghcr.io/osgeo/gdal:alpine-small-latest` or `python:3.12-slim` + GDAL installed.
  - Working directory: `/workspace`.
  - Volumes: `./packages/wayfinding:/workspace/packages/wayfinding:rw`,
    `C:/repos/sfudt/claude/dtwin-harness/data/IndoorWayfinding.gdb:/data/IndoorWayfinding.gdb:ro`.
  - Command: `/bin/sh` (overridden by `docker compose run --rm test <cmd>`).
- Duration: 1.5 hours (researching GDAL-enabled Python images, testing mount paths on Windows).

### Step 4: Makefile gates (implementer)
- Create `Makefile` with targets:
  - `test`: `docker compose -f infra/docker-compose.yml run --rm test pytest packages/wayfinding/tests --cov=packages/wayfinding/src --cov-report=term --cov-fail-under=85`.
  - `lint`: `docker compose -f infra/docker-compose.yml run --rm test ruff check packages/wayfinding`.
  - `type`: `docker compose -f infra/docker-compose.yml run --rm test pyright packages/wayfinding/src`.
  - `.PHONY: test lint type`.
- Duration: 1 hour.

### Step 5: Gate smoke tests (implementer)
- Create `tests/gate/test_no_host_python.sh`: grep `Makefile` for bare `python`/`pip`/`pytest`
  invocations (should find none).
- Create `tests/gate/test_gdb_readonly.sh`: verify Docker Compose volume has `:ro` suffix.
- These are not run by `pytest` — they are shell scripts run by `test-runner` as a pre-gate sanity
  check.
- Duration: 0.5 hours.

### Step 6: DOD update (implementer)
- Update `docs/DOD.md` § Coverage floors: set `packages/wayfinding: 85%` as the initial floor.
- Duration: 0.25 hours.

## Risks and mitigations

| Risk | Severity | Mitigation |
| --- | --- | --- |
| Windows path mounts (`C:\...`) incompatible with Docker Compose | High | Test both `C:/repos/...` forward-slash and `/c/repos/...` Git Bash path conventions in `docker-compose.yml`; document the working form in ADR-0002. |
| GDAL installation in the container adds minutes to build time | Medium | Use a pre-built image (`ghcr.io/osgeo/gdal:alpine-small-latest`) instead of installing from scratch; accept the ~800 MB image size for Phase 1. Optimize in Phase 2+ if build time becomes a bottleneck. |
| Coverage floor set too high for early-stage code | Low | 85% is the reference implementation's floor; we match it. Can be revised per-package in a future ADR if justified. |
| Gate tests pass but a fresh checkout fails due to missing steps | Medium | Explicit AC #6 requires running from a clean checkout. `test-runner` must test this, not just run in an already-configured environment. |

## Rollback / migration notes

This is the first package; there is no prior state to migrate from. If this ticket is abandoned
mid-implementation, delete `packages/`, `infra/`, and the `Makefile`; revert `docs/DOD.md` and
`docs/adr/0002-*`.

## ADR requirement

**Yes, ADR-0002 is required before `test-writer` starts.** Invoke `architect` after `planner`
approval of this plan.

tool choices (ruff/mypy/pyright), and the `:ro` mount rule for the source GDB. These are boundary
decisions that affect every future package added in Phase 1+.
