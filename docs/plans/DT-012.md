# DT-012: Phase 1 Developer Standup

**Status:** Implemented; full-suite verification blocked by unpublished ADR-0006 image digest
**Date:** 2026-09-09
**Phase:** 1 (Developer tooling)

## Objective

Complete the existing PowerShell and POSIX stack launchers so a developer can build and stand up
the Phase 1 container workspace, keep it running for interactive use, and optionally run all
required artifact-only gates. This is a developer workspace, not an API or production deployment.

## Scope

- Keep the `artifact` and `source-etl` Compose services alive after `docker compose up -d --wait`.
- Add a health check that verifies the prebuilt Python/GDAL toolchain without host execution.
- Add `-Test` and `--test` launcher options that run `test`, `lint`, `type`, and `dataqa` in the
  running `artifact` container.
- Add matched teardown scripts that destroy only the explicitly selected Compose project, preserve
  volumes by default, and remove volumes only when requested.
- Preserve isolated Compose projects, free-port selection, local-image build support, dry-run
  behavior, read-only source data, and non-zero gate failures.
- Document commands for PowerShell and POSIX shells.

## Acceptance Criteria

1. Both launchers expose equivalent test options and run the same four containerized gates.
2. `--dry-run` and `-DryRun` print standup and gate commands without changing container state.
3. A normal launch leaves both Phase 1 capability containers running and healthy.
4. A test launch fails immediately when any gate fails and preserves the gate exit status.
5. No Python, GDAL, package installer, or database client runs on the host.
6. The source geodatabase remains mounted read-only only on `source-etl`.
7. Existing launcher collision and argument tests continue to pass.
8. PowerShell and POSIX teardown scripts support the same project, local-image, volume-removal, and
  dry-run options without rediscovering ports or affecting other Compose projects.

## Tests

- Launcher contract test verifies the POSIX `--test` path invokes all four gates.
- Launcher parity checks verify the PowerShell script exposes the same gate commands.
- Compose contract checks verify persistent commands and health checks exist.
- Existing collision, exhaustion, invalid-name, and dry-run tests remain green.

## Architecture

No ADR is required. This completes the developer lifecycle of the existing Phase 1 capability
containers and does not add a runtime service, schema, API, or component boundary.

## Verification

- Launcher contract gate: PASS, including collision handling, shell parity, fail-fast behavior,
  exact POSIX gate-exit propagation, and project-scoped teardown behavior.
- Compose configuration: PASS.
- PowerShell standup: PASS; the local image built and both services reached `healthy`.
- Full package gate: blocked by the pre-existing `sha256:PUBLISHED_DIGEST_REQUIRED` placeholder
