# DT-015: LAN Click-to-Route Demo

**Status:** Planned
**Date:** 2026-09-10
**Phase:** Cross-phase stakeholder demo
**Depends on:** DT-013, DT-014, ADR-0008, ADR-0009, ADR-0010
**ADR:** [ADR-0010 trusted-LAN demo publication and route-entry parity](../adr/0010-trusted-lan-demo-and-route-entry-parity.md)

## Problem and scope

DT-014 proves deterministic room-to-room routing, but its host port is loopback-only, route endpoints
are tedious 1,017-item selects, map clicks only inspect rooms, and assistant route responses are not
rendered through the map route workflow. Publish the demo on the host's LAN interface, report a
machine-name URL, make the first room activation set origin and the second set destination and
immediately request/render the route, and make exact assistant directions render the identical route
response. Preserve the manual selectors as an accessible correction/fallback path.

Before UI implementation, containerized data QA must select and publish three replayable successful
routes from the accepted artifacts:

1. Strand Hall same-level corridor route with distinct anchors and non-trivial pathway geometry.
2. AQ same-level corridor route with distinct anchors and non-trivial pathway geometry.
3. AQ multi-level route containing a real stairs or elevator transition; prefer an
   `elevator_only` fixture when the measured graph supports one.

Exact endpoint IDs are deliberately not guessed: current DT-014 evidence verifies only ECC 118 to
ECC 3163. Selection must be deterministic from eligible AQ/Strand endpoints, require `200`, distinct
anchors, positive distance, non-empty geometries, and the stated facility/level/mode constraints.

## Non-goals

- No graph, endpoint-anchor, shortest-path, instruction, API, schema, or component-boundary change.
- No fake room connectors, inferred gap edges, cross-level snapping, public/outdoor geometry,
  revised-source promotion, nearest search, travel-time estimate, LLM, or internet deployment.
- No claim that room-to-anchor traversal is walkable or that elevator-only is wheelchair-certified
  or guaranteed step-free.

## Acceptance criteria

1. ADR-0010 supersedes only ADR-0007's loopback deployment boundary and defines trusted-LAN scope,
  no-auth/plain-HTTP disposition, Host validation, rate and concurrency limits, bounded logging,
  patching, monitoring, firewall guidance, explicit warning, configurable rollback, and expiry
  conditions for this exception.
2. Compose publishes the selected demo port on `${DTWIN_DEMO_BIND_ADDRESS:-0.0.0.0}`; the server
  remains container-bound on `0.0.0.0`, and both launchers report
  `http://<machine-name>:<port>/` after checking port availability on all interfaces. Machine-name
  discovery uses only local OS facilities, and the URL works from a second LAN host by machine name.
3. LAN exposure is explicit in startup output and documentation, remains offline/artifact-only, and
   implements every control required by the new ADR. No permissive CORS or raw filesystem/data
   endpoint is added.
4. First pointer or keyboard activation of a room sets origin; second distinct activation sets
   destination and automatically posts the unchanged DT-014 route contract using the selected
   profile. A new first activation after a completed/failed route starts a new pair.
5. Origin and destination have persistent, non-color-only map/list states and announced labels.
   Re-selecting, swapping, clearing, or correcting either endpoint through the existing selects is
   deterministic and never submits an incomplete pair.
6. Every successful click route draws only `response.geometries` for the active level and renders
   the existing graph distance, steps, anchors, provenance, and warnings. Failures clear stale
   geometry and show the exact DT-014 failure/disclosure.
7. Direct, click, and exact chat directions use one client command that makes exactly one
  `POST /demo/v1/route` and passes success or failure to the same `renderRoute` path. For equal
  IDs/profile, status, edges, distance, geometry, steps, reachability, warnings, provenance, and
  accessibility disclosure are identical; the browser never also posts the same route to the
  assistant endpoint.
8. Ordinary assistant directions use `default`; mobility wording uses `elevator_only`, never falls
   back to stairs, and visibly says elevators only/stairs excluded with `door_width`, `path_width`,
   `slope`, `powered_doors`, and `surface` unverified on success and failure.
9. No client or server code computes geometry, distance, routing, reachability, or accessibility.
   All three entry paths delegate to the existing deterministic `RoutingService` result.
10. A canonical checked-in DT-015 evidence report contains the three AQ/Strand fixtures, artifact
    hashes, endpoint/reachability fields, profile, ordered edge IDs/modes, per-level geometries,
    distance, steps, and selection rationale; replay is byte-stable and rejects artifact drift.
11. Desktop and mobile browser checks cover pointer and keyboard two-room selection, cross-floor
    step navigation, assistant parity, disclosures, no overlap, and a real second-device LAN load.
12. All discovery, tests, gates, and runtime execution are container-only; source geodatabases and
    accepted build artifacts remain read-only and no startup package installation is introduced.

## RED tests

- `test_dt015_demo_publishes_selected_port_on_all_interfaces` - fails while Compose publishes only
  `127.0.0.1` and the ADR-required controls are absent.
- `test_dt015_launchers_report_machine_name_url_and_lan_warning` - fails while launchers print only
  a loopback URL; dry-run must remain side-effect free.
- `test_dt015_lan_security_contract` - fails until Host handling, CORS, headers, limits, logging, and
  other controls exactly match the accepted deployment ADR.
- `test_first_room_activation_sets_origin_without_request` - fails because `selectUnit` only shows
  record details.
- `test_second_distinct_room_activation_sets_destination_and_routes` - fails because clicks do not
  populate endpoints or submit `/demo/v1/route`.
- `test_keyboard_room_activation_matches_pointer_state_machine` - fails until Enter/Space uses the
  same origin/destination state and live announcements.
- `test_endpoint_clear_swap_reselect_and_manual_select_fallback` - fails until correction controls
  avoid stale or incomplete requests.
- `test_route_failure_clears_stale_overlay_and_keeps_disclosures` - fails until automatic failures
  use the existing exact failure renderer without old geometry.
- `test_assistant_success_renders_same_route_as_direct_request` - fails because assistant results
  are treated as lookup text and never call `renderRoute`.
- `test_assistant_failure_and_mobility_disclosure_match_route_service` - fails until assistant
  errors and elevator-only results share direct-route rendering verbatim.
- `test_dt015_three_demo_routes_are_real_deterministic_and_replayable` - fails until canonical
  evidence contains the Strand corridor, AQ corridor, and AQ transition fixtures with exact hashes.
- `test_dt015_routes_use_only_recorded_edges_and_no_connector_geometry` - fails on any fabricated
  edge, unverified room segment, prohibited profile mode, or geometry not returned by the service.
- Browser smoke: fails until the three evidence fixtures render nonblank at desktop/mobile sizes,
  keyboard flow works, assistant/direct outcomes match, and a second LAN host reaches machine name.

## Risks and mitigations

- **LAN attack surface:** shared access invalidates ADR-0007's localhost assumptions. Mitigate with
  the mandatory ADR, explicit trusted-LAN boundary, its enforced controls, and one-command rollback.
- **Fragmented graph:** 816/840 components may prevent a desired showcase pair. Select only measured
  successful fixtures; fail evidence generation rather than bridge a gap or silently change profile.
- **False connectors:** room centroids are approximate anchors, not walkable geometry. Draw/narrate
  only graph edges and retain both attachment distances and room-to-anchor warning.
- **Accessibility correctness (G1-G3):** no path width, slope, surface, powered-door, or door-width
  evidence exists. Elevator-only means stairs excluded and must carry the complete unverified list.
- **UI race/stale route:** rapid clicks or assistant requests could render an older response.
  Serialize or supersede requests by selection generation and test stale-response rejection.

## Rollback

Set `DTWIN_DEMO_BIND_ADDRESS=127.0.0.1` and restart, or use the checked-in teardown launcher,
retaining DT-014 routing. Remove only DT-015 client behavior and evidence; do not alter artifacts,
graph logic, ADR-0008/0009, or source data.
