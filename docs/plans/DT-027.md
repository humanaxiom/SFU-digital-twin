# DT-027: Windows PowerShell launcher startup

Date: 2026-10-08
Status: Complete — verified local-image launcher repair; published registry access remains unavailable

Windows PowerShell 5.1 evaluates the default ComposeFile expression before
PSScriptRoot is populated, so startup fails in Join-Path before reaching Docker.
The paired teardown script has the same defect.

Resolve omitted ComposeFile paths in the script body in both PowerShell wrappers;
preserve explicit paths, port isolation, Docker-only execution and image selection.
The supported repository-root command remains tools/launch-stack.ps1. No schema,
API or capability boundary changes; ADR-0006 and DT-012 remain applicable.

Acceptance: capture Windows PowerShell RED; add Docker-run regression coverage;
verify omitted and explicit paths from another working directory; run launcher
contracts and full artifact gates; perform fresh real startup, browser/API route
checks and project-scoped teardown. Use a separate project/port for verification
and preserve the stopped candidate deployment and its artifacts. Record local
image use separately from published-image access. Update handoff and changelog,
then obtain independent large-model final review.

Verification uncovered two inherited harness issues: CRLF shell scripts prevent
the Docker launcher gate from running, and demo.cjs expects clicking a known
disconnected room to POST a failed route. Pin the three launcher shell files to
LF and migrate that browser assertion to DT-024 N15 (disabled room, no POST).
Retain direct unsupported-route API coverage; no application behavior changes.

Verification and independent acceptance: [DT-027 report](../reports/DT-027.md).
