# DT-013: Artifact-Backed Demo Explorer

**Status:** Implemented — pending final gate
**Date:** 2026-09-09
**Phase:** Cross-phase stakeholder demo
**ADR:** ADR-0007

## Objective

Deliver a visual, clickable browser interface over the real normalized GeoPackage with a disclosed
deterministic data assistant. The demo must be useful to Facilities, CIO, and AI-policy reviewers
without presenting unavailable routing, proximity, live-status, or LLM capabilities.

## Scope

- Add an artifact-only demo HTTP service using Python standard library and installed OGR bindings.
- Serve facilities, vertically ordered levels, per-level scenes, unit details, and deterministic
  assistant responses under `/demo/v1`.
- Render real level, room, detail, and landmark geometry as an interactive SVG floor explorer.
- Add pointer and keyboard room selection, facility/floor controls, real room lookup, evidence,
  artifact identity, and limitations disclosure.
- Refuse route, nearest, distance, travel-time, and path-accessibility requests explicitly.
- Add the `demo` Compose service and integrate it with launch/teardown scripts.

## Acceptance Criteria

1. The service fails closed without `build/wayfinding.gpkg` or required normalized layers.
2. Health reports the artifact SHA-256 and capability limitations.
3. API counts match the artifact: 3 facilities, 11 levels, 1,017 units, and 40 landmarks.
4. Scenes contain only records for the requested `level_id` and explicit public fields.
5. Floor controls use `vertical_order`; real geometry renders non-empty and is clickable.
6. Unit selection displays source-derived room, category, use type, and provenance values.
7. The assistant deterministically resolves exact room IDs, lists levels/facilities/landmarks,
   returns bounded literal matches, and attaches evidence.
8. Unsupported route/proximity requests are refused without generated geometry or distances.
9. Mobility requests disclose elevator-only routing is not implemented and list unverified path
   properties; no path accessibility claim is made.
10. Static assets are local-only, use safe DOM text insertion, and include keyboard alternatives.
11. The demo binds to loopback through a launcher-selected port and mounts the GeoPackage read-only.
12. All runtime and tests remain container-only with no startup package installation.

## Tests

- API startup, health, security headers, method, body-size, malformed-input, and traversal tests.
- Artifact count, level-order, scene-filtering, field-allowlist, and provenance tests.
- Assistant supported-intent, ambiguity, refusal, mobility disclosure, injection, determinism, and
  evidence tests.
- Static-client contract tests for local assets, semantic controls, SVG interaction, safe text APIs,
  limitations, and absence of route/LLM branding.
- Compose and launcher tests for artifact-only read-only mounting, health, port selection, and
  checked-in commands.
- Browser smoke checks for real nonblank geometry, click interaction, chat response, keyboard flow,
  desktop/mobile layout, and no overlap.

## Non-Goals

Routing, unit connectors, nearest-place ranking, turn instructions, FTS5, PMTiles, MapLibre, live
status, authentication, remote deployment, or LLM integration. These remain later production
phases and are never simulated in this demo.

## Validation

- 33 DT-013 service, static-client, and deployment tests pass in the artifact container.
- Ruff and Pyright pass; the launcher lifecycle gate passes.
- Browser checks at 1440×900 and 390×844 verify nonblank real geometry, room and landmark
