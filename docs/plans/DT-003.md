## 1. Objective

Extract all seven AIIM layers from the read-only File Geodatabase (`IndoorWayfinding.gdb`) into a
working GeoPackage, preserving the native **EPSG:26910** coordinate system for all metric
computations while also providing an **EPSG:4326** copy for web client display.

The output GeoPackage serves as the working database for all subsequent ETL stages (normalisation,
graph construction, search indexing) and eliminates direct dependencies on the proprietary FileGDB
format downstream.

### 2.3 Design rationale: dual CRS strategy

**Why keep EPSG:26910?**
- All distance/length calculations must be in metres (routing costs, snapping tolerances,
  thresholds). The source `LENGTH_3D` field is already in metres (EPSG:26910).
- Computing distances in EPSG:4326 (decimal degrees) requires spherical/ellipsoidal maths and
  introduces accuracy risk for small indoor features.

**Why add EPSG:4326?**
- MapLibre GL and all modern web mapping libraries expect WGS84 lat/lon.
- Reprojecting on every API response is wasteful; pre-compute it once during ETL.

**Invariant:** EPSG:26910 is the **source of truth** for all geometry operations. EPSG:4326 is a
display artifact only.

## 4. Implementation Steps

### Step 1: Design the extraction function signature and error handling (0.5 day)

**File:** `packages/wayfinding/src/wayfinding/etl/extract.py`

```python
from pathlib import Path
from typing import Literal

def extract_to_gpkg(
    gdb_path: Path,
    gpkg_path: Path,
    overwrite: bool = False
) -> dict[str, int]:
    """Extract all AIIM layers from FileGDB to GeoPackage with dual CRS.
    
    Args:
        gdb_path: Path to source IndoorWayfinding.gdb (must exist, read-only)
        gpkg_path: Output GeoPackage path (will be created/overwritten)
        overwrite: If True, delete existing gpkg_path before extraction
        
    Returns:
        Dictionary mapping layer name to feature count for verification
        
    Raises:
        FileNotFoundError: If gdb_path does not exist
        RuntimeError: If ogr2ogr extraction fails for any layer
        PermissionError: If gdb_path is not readable or gpkg_path not writable
    """
```

**Design decisions:**
- Use `subprocess` to invoke `ogr2ogr` (available in the GDAL container) rather than Python GDAL
  bindings initially — simpler, more robust, easier to debug via shell commands.
- Return feature counts for immediate verification in the calling code.
- Make overwrite explicit (fail-fast if output exists unless confirmed).

### Step 2: Implement extraction loop for EPSG:26910 layers (1 day)

**Pseudocode:**

```python
LAYERS = [
    "Facilities_AQ_SH_ECC",
    "Levels_AQ_SH_ECC",
    "Units_AQ_SH_ECC",
    "Pathways_AQ_SH_ECC",
    "Transitions_AQ_SH_ECC",
    "Landmarks_AQ_SH_ECC",
    "Details_AQ_SH_ECC",
]

for layer_name in LAYERS:
    output_layer_name = layer_name.replace("_AQ_SH_ECC", "_26910")
    
    # ogr2ogr command:
    # -f GPKG                        (output format GeoPackage)
    # -append                        (for layers 2-7, first uses -update)
    # -nln <output_layer_name>       (new layer name)
    # -lco GEOMETRY_NAME=geom        (standardise geometry column)
    # -preserve_fid                  (keep original FID if possible)
    # <gpkg_path> <gdb_path> <layer_name>
    
    cmd = [
        "ogr2ogr",
        "-f", "GPKG",
        "-append" if i > 0 else "-update",  # -update creates file if missing
        "-nln", output_layer_name,
        "-lco", "GEOMETRY_NAME=geom",
        str(gpkg_path),
        str(gdb_path),
        layer_name,
    ]
    
    subprocess.run(cmd, check=True, capture_output=True)
    
    # Verify feature count using ogrinfo
    count = get_feature_count(gpkg_path, output_layer_name)
    feature_counts[output_layer_name] = count
```

**Gotchas:**
- First `ogr2ogr` call should not use `-append` because the GeoPackage doesn't exist yet; use
  `-update` which creates if missing, then `-append` for subsequent layers.
- Capture `stderr` from `subprocess.run` and include it in raised `RuntimeError` on failure for
  debugging.
- 3D geometry is preserved by default with GDAL; verify with `ogrinfo -so` after extraction.

### Step 3: Implement reprojection loop for EPSG:4326 layers (0.5 day)

**Pseudocode:**

```python
for layer_26910 in LAYERS_26910:
    layer_wgs84 = layer_26910.replace("_26910", "_wgs84")
    
    # ogr2ogr command for reprojection:
    # -t_srs EPSG:4326               (target CRS)
    # -dim XY                        (drop Z for web compatibility)
    # -nln <layer_wgs84>
    # <gpkg_path> <gpkg_path> <layer_26910>
    
    cmd = [
        "ogr2ogr",
        "-update",
        "-append",
        "-t_srs", "EPSG:4326",
        "-dim", "XY",
        "-nln", layer_wgs84,
        str(gpkg_path),
        str(gpkg_path),
        layer_26910,
    ]
    
    subprocess.run(cmd, check=True, capture_output=True)
    feature_counts[layer_wgs84] = get_feature_count(gpkg_path, layer_wgs84)
```

**Why drop Z for WGS84 layers?**
- Z values in EPSG:4326 are ambiguous (height above ellipsoid? MSL? CGVD28?).
- Web clients don't use Z for 2D indoor maps.
- Simplifies JSON serialisation (2-element arrays instead of 3-element).

### Step 5: Wire up `make etl-extract` target (0.25 day)

**In `Makefile`:**

```makefile
.PHONY: etl-extract
etl-extract:  ## Extract FileGDB to GeoPackage (dual CRS)
	docker compose run --rm etl python -m wayfinding.etl.run extract
```

**In `packages/wayfinding/src/wayfinding/etl/run.py`:**

```python
import sys
from pathlib import Path
from wayfinding.etl.extract import extract_to_gpkg

def main():
    if len(sys.argv) < 2:
        print("Usage: python -m wayfinding.etl.run <command>")
        sys.exit(1)
    
    command = sys.argv[1]
    
    if command == "extract":
        gdb_path = Path("/data/IndoorWayfinding.gdb")
        gpkg_path = Path("/workspace/build/wayfinding.gpkg")
        gpkg_path.parent.mkdir(parents=True, exist_ok=True)
        
        counts = extract_to_gpkg(gdb_path, gpkg_path, overwrite=True)
        
        print("Extraction complete. Feature counts:")
        for layer, count in sorted(counts.items()):
            print(f"  {layer}: {count}")
    else:
        print(f"Unknown command: {command}")
        sys.exit(1)

if __name__ == "__main__":
    main()
```

## 6. Risks and Gotchas

### 6.1 GDAL image setup

**Risk:** DT-002's ETL container may use a Python-only image without GDAL.

**Mitigation:** In Step 6, validate GDAL availability. If missing, update
`infra/docker-compose.yml` to use `ghcr.io/osgeo/gdal:alpine-small-3.8.4-python`. This is
technically an amendment to DT-002 but is trivial (1-line image change) and safe to do in DT-003.

### 6.2 CRS reprojection accuracy

**Risk:** Reprojecting fine-grained indoor geometries (mean segment 0.94 m in EPSG:26910) to
EPSG:4326 and back may accumulate error if downstream code mistakenly computes distances in WGS84.

**Mitigation:** Document the invariant loudly: **EPSG:26910 is the source of truth**. All distance
calculations, snapping, and routing happen in 26910. EPSG:4326 is display-only. Add a test in
DT-005 (graph snapping) that verifies snapping tolerance is applied in 26910, not 4326.

### 6.3 3D vs 2D geometry confusion

**Risk:** Downstream code may assume 2D geometry because the `_wgs84` layers are 2D.

**Mitigation:**
- Use explicit layer naming: `*_26910` is always 3D, `*_wgs84` is always 2D.
- Schema enforcement: Pydantic models in `schema.py` should validate geometry dimension where it
  matters (e.g., `LENGTH_3D` from 26910 layers must have Z).

### 6.4 Large layer extraction time

**Risk:** `Details_AQ_SH_ECC` has 55,593 features; extraction may take minutes.

**Mitigation:**
- Not a blocker (ETL is offline, runs once per data refresh).
- If it becomes a bottleneck, parallelize extraction per layer (not needed for v1).
- Monitor: add timing to `extract_to_gpkg()` return value (optional enhancement).

### 6.5 SQLite page-level determinism

**Risk:** Test 13 (`test_extract_deterministic`) may fail due to SQLite internal page allocation
order even if feature data is identical.

**Mitigation:**
- Don't compare raw file bytes; compare feature counts, geometries, and attributes at the data
  layer (using `ogrinfo` or GDAL Python API).
- If flaky, relax to "feature data deterministic" instead of "file byte-identical".

### 6.6 File locking on Windows

**Risk:** Docker Desktop on Windows may not enforce `:ro` mount semantics correctly; or FileGDB may
lock on read.

**Mitigation:**
- Test on the target Windows environment early (Step 6 validation).
- Gate test `test_gdb_readonly.sh` must pass; if it fails, escalate as a blocker.
- Worst case: copy GDB to a temp location inside the container before reading (preserves immutability
  boundary even if not enforced by mount).
