## Objective

Show all Burnaby campus buildings in a campus overview and, where the admitted data
supports it, calculate room-to-room or building-to-building journeys across indoor,
entrance and outdoor route legs. A visible building must not imply that it is routable.
Every displayed route segment and every building-boundary crossing must be backed by
versioned source data.

This ticket is intentionally staged. The campus overview can ship before campus-wide
routing. Ordinary pedestrian routing and verified accessibility are separate admission
gates.

## Scope definition

“All buildings” means the complete authoritative Burnaby campus inventory, including
an explicit decision on residences, leased space, service buildings and restricted
facilities. Local indoor detail currently covers only AQ, ECC and Strand Hall. Each
building therefore needs a coverage status:

- overview only;
- verified entrance destination;
- partial indoor coverage;
- full indoor routing; or
- separately verified accessible routing.

The first release may show every building for which authoritative footprint and
identity data are supplied while routing only supported pairs. It must explain missing
coverage precisely and preserve the user's selected origin and destination.

## Evidence and current constraints

  not a campus-wide building catalog.
- The DT-022 candidate joins AQ and ECC: 8,220 AQ↔ECC eligible room pairs are reachable
  in both existing profiles. It provides zero Strand↔AQ/ECC room pairs and remains
  unpromoted.
- The revised source adds pathways FIDs 22427–22567: 141 single-part features totaling
  12,800.80 m over roughly 1.72 by 0.86 km. All lack facility and level IDs. Of these,
  140 have vertical order 0, one has 1, and 134 contain zero-valued Z coordinates.
- The additions form 43 literal exact-XYZ source components. The largest, with 659
  vertices, touches both AQ and Strand source vertices. This is a GIS review lead, not
  proof of a public or same-grade connection.
- Nine revised features end exactly on known indoor vertices: SH 22429/22452 and AQ
  22471/22473/22497/22498/22534/22540/22562. Features 22496 and 22561 intersect both
  AQ and ECC footprints. Neither fact authorizes inferred topology.
- AdditionalData contains 82 entrances, 82 main doors, 34 ramps and 262 photo
  attachments. It lacks facility/path joins, uses mixed `ReferenceLevel` codes, has
  Z=0 geometry and is primarily from 2022. ADR-0008 keeps it out of the public graph.
- Existing routing already uses a global graph, so cross-building endpoints are not
  blocked by an artificial same-facility rule. The missing contracts are campus
  geometry, outdoor topology, portals, coverage and journey semantics.
- Current scenes are one indoor level at a time. Guidance v1 represents floor visits
  and stairs/elevators, but cannot express exit, outdoor and entrance legs.

## P0 GIS data gate

Campus-wide routing is no-go until GIS provides or confirms the following:

1. A complete Burnaby building inventory with stable facility/site IDs, official
   names, acronyms, aliases, footprints, operational status and an identity crosswalk
   to Room Finder and existing indoor `FACILITY_ID` values. Resolve ECC versus EDB
   naming inconsistencies.
2. Classification of revised pathway FIDs 22427–22567 as indoor hallway, outdoor
   sidewalk, covered walkway, bridge, tunnel, stair, ramp, plaza or non-routing
   cartography, including correct grade/level, access, direction, intended junctions,
   source lineage and verification status.
3. A connected, noded pedestrian network covering paths, plazas, crossings, stairs,
   ramps, bridges and tunnels. Crossing or coincident geometry must carry explicit
   same-grade connectivity; absence of a junction must be representable.
4. Stable portal records connecting entrance ID → facility/local level → door ID →
   indoor path/node → outdoor path/node. Include surveyed position, public label,
   direction, hours/restrictions and ordinary-pedestrian verification.
5. A documented horizontal CRS and vertical datum. Missing elevation must remain
   unknown rather than silently becoming ground level.
6. Current ownership, snapshot/revision dates and field definitions. Unknown and
   unverified values must remain explicit.

Accessibility is a later, independent gate. It requires current slope/cross-slope,
clear width, surface, curb-ramp, powered-door, step-free continuity, elevator access
and restriction evidence for every edge and portal in a claimed route.

Delivery-level GIS acceptance checks:

- every routable building has at least one verified public entrance;
- every published entrance has an authored indoor and outdoor attachment;
- all path intersections declare grade and connectivity;
- no route relies on polygon proximity, centroid lines or inferred crossings;
- stable identifiers survive successive source exports; and
- ordinary and accessible verification status is attached to source evidence.

The full request should be kept synchronized in `docs/requests/GIS-DATA-NEEDED.md`.

## Architecture decisions required before implementation

Write a new ADR covering these decisions before changing the public artifact contract:

1. **Campus overview and coverage.** Add versioned facility geometry and coverage
   metadata without merging all floor polygons into one indoor scene.
2. **Outdoor node identity.** Keep deterministic EPSG:26910 metric calculations and
   `MultiDiGraph` parallel edges, but do not assign fabricated indoor `vertical_order`
   values to outdoor paths. Represent surface and grade-separated topology explicitly.
3. **Portals.** Building crossings are authored entities with stable IDs and exact
   indoor/outdoor endpoints. Coincident XY or intersecting geometry is insufficient.
4. **Journey contract.** Introduce a versioned response with ordered indoor, outdoor,
   portal and building-connector legs. Each instruction and selected span references
   exact edge occurrences/source geometry.
5. **Endpoint kinds.** Model room, entrance and building destinations explicitly;
   do not overload `unit_id`. A building destination resolves only to a verified,
   policy-eligible entrance.
6. **Profiles and reachability.** Preserve current `default` and `elevator_only`
   meaning during migration. Outdoor stairs must be excluded from elevator-only.
   Do not rename it accessible. Once one-way portals exist, availability must use
   directed reachability rather than weak-component membership alone.
7. **Source admission.** Keep current accepted artifacts frozen until an isolated
   candidate comparison and explicit promotion decision. Preserve parallel edges,
   measured distances, repeated building/floor visits and explicit route failures.

Exit: scope, identifiers, source authority, admitted layers and known unsupported

### Stage 1 — campus overview

- Add a versioned overview/coverage artifact and API response with building geometry,
  labels, bounds, known entrances and capability status.
- Default the UI to a campus overview with Campus / Building / Floor context.
- Support search and selection by building name/acronym as well as room.
- Selecting a building reveals its real floors. Overview visibility remains independent
  of route availability.
- Frame all buildings predictably at desktop, mobile and 320 px. Preserve deliberate
  manual camera state and expose meaningful reset/zoom actions.

Exit: all admitted buildings can be found and inspected without implying routes or
indoor detail that do not exist.

### Stage 2 — verified AQ/ECC/SH pilot

- Admit only reviewed pathway/portal data and build an isolated candidate.
- Expose only ordered building pairs and profiles that are actually reachable.
- Provide explicit failures such as “No mapped outdoor connection to this entrance.”
- Never draw straight centroid-to-centroid or polygon-proximity connections.

Exit: each shown boundary crossing has an authored source relationship and every
painted segment is present in the candidate graph.

### Stage 3 — journey UI and guidance

- Present a chronological journey such as indoor floor → named exit → outdoor or
  covered path → named entrance → destination floor.
- Use one detailed floor at a time. A campus preview may collapse indoor legs but must
  distinguish collapsed summaries from actual outdoor geometry.
- Provide Whole journey, Current leg and Whole floor framing.
- Selecting an instruction changes context when required and highlights the exact
  corresponding route segment. Repeated building/floor visits remain repeated.
- A bridge between differently named local floors must be described as a building
  connection, not automatically as stairs or a floor change.

Exit: instructions are understandable to a visitor and remain traceable to route data.

### Stage 4 — campus expansion

- Add buildings first as overview-only, then verified-entrance destinations, then
  indoor routing as data arrives.
- Add outdoor restrictions and time-dependent availability only when the source and
  evaluation time contract are defined.
- Admit accessibility claims through their own evidence and regression gates.

Exit: coverage expands without weakening topology, provenance or user disclosure.

## Go/no-go rules

- **Overview GO:** authoritative identity and usable footprint/location data exist;
  missing indoor or routing coverage is explicit.
- **Pilot routing GO:** every segment is admitted, every facility boundary uses a
  verified portal and candidate-backed route/guidance/UI E2E passes.
- **Campus-wide routing NO-GO:** the pedestrian network or entrance joins are
  incomplete or unclassified.
- **Accessibility NO-GO:** any required slope, surface, width, door, restriction or
  elevator evidence is missing or stale.
