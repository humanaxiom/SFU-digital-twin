## Problem and outcome

### Follow-up — visible room browsing and compact navigation

User feedback after PR #4: excessive scrolling, building view appears to have no
rooms, and navigation must offer clickable choices rather than only dropdowns.
Implement persistent building/floor buttons above the map; building actions open
the remembered/default recorded floor directly. Keep exact-ID state and stale
response protection. Expose a filterable room button list next to the floor map,
with explicit empty-floor coverage. Compact navigation and toolbars so a useful
map is visible without page scrolling on 390px and 320px screens. Secondary
dropdowns remain available in an expandable control group. This follow-up also
synchronizes journey-floor selection with its first instruction; it does not complete
endpoint draft/commit or the remaining journey/exploration work.
Capture browser RED, then run focused/full Docker gates, fresh task/browser/API
checks and independent review. The lead owns production; separate large-model
review and small-model browser work have nonoverlapping file ownership.

The deployed client can silently switch buildings when choosing a floor, return to
an old route floor after a newer selection, and display a journey floor unrelated
to the instruction advanced by Next. Endpoint dropdowns contain 1,017 rooms, mix
connected and disconnected destinations, and automatically submit despite an
explicit Show directions action. Mobile puts essential instruction context below
the map. Existing passing fixtures do not establish coherent user-task navigation.

Deliver one predictable process: choose building/floor to explore; search From/To;
preview a committed route; advance a synchronized floor/transition journey; inspect
other rooms/floors without losing that route; return deliberately to the journey.

## Intended interaction contract

1. All buildings stay available. Floors are scoped to the inspected building and
   keyed by exact level_id; a floor choice never changes building. Explicit Open
   floor handles an already-selected floor. Missing floors are labeled unavailable.
2. Searchable, keyboard-operable endpoint inputs show room identity, building and
   floor. Stable selections survive asynchronous result refresh. Connection status
   is distinct from geometry/guidance quality and does not hide unsupported rooms.
3. Editing From/To/profile changes a draft. Preview route commits once. The prior
   map remains clearly labeled with its committed endpoints/profile until success;
   pending or failed Elevator only edits must never relabel a retained stairs route.
4. Journey floor selection chooses its first instruction; map, active visit, selected
   step and Next/Previous update together. Repeated-floor visits retain distinct IDs.
   Express elevator skips stay skipped; departure/arrival controls name both levels.
5. Manual floor browsing enters exploration. A visible Return to route replaces
   Next/Previous there. It restores the committed step without implying live position.
6. Assistant directions resolve a draft and require the same explicit Preview route action. Room click selects a record, not a route endpoint. Start here/Directions here
   explicitly edit draft endpoints. Clear route clears pending/committed route, endpoint draft and availability while preserving inspected room/floor/building/camera.
7. Loading names requested and displayed floors. Errors retain a correctly labeled
   last good scene and Retry. Newest deliberate navigation intent wins over every
   delayed route, scene, availability and unit-detail completion.
8. Mobile keeps current instruction, transition action and route-return affordance
   reachable beside the visible map. Preserve keyboard focus, announcements, 44px
   touch targets where appropriate, readable layout at 320px, and reduced motion.

## Architecture and ownership

The lead owns the ADR, transition contracts, integration and acceptance. Give
bounded workers explicit non-overlapping files after module boundaries are agreed:
state/request layer; endpoint UI; journey/map presentation; task-based browser tests.
Do not let multiple workers concurrently patch the monolithic app.js. Split modules
only after the state contract and RED tests exist. Large-model independent review
checks the integrated state behavior and evidence; workers do not self-approve.

State authority: context, inspected facility, requested/displayed floor and load
status, selected room, draft and committed route, visit/step, explore/follow mode,
per-floor camera. DOM controls render state and never serve as identity storage.
All asynchronous requests have resource keys plus intent tokens; cancellation is
an optimization, token validation is correctness. Route completion can store a
result without stealing a newer explicit map selection.

Scene cache key is artifact hash plus exact level ID. Deduplicate in-flight loads;
lazily prefetch adjacent route visits. Measure transfer, JSON parse and SVG render
separately before introducing precomputation/compression. Preserve source geometry.
