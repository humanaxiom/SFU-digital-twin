# DT-034 — Restore two-room click directions

Date: 2026-11-20
Status: Locally verified and independently reviewed; see [evidence](../reports/DT-034.md).

The user reported that the running demo at `http://127.0.0.1:18107/` no
longer creates directions after clicking one room and then another. Stage C
intentionally changed those clicks to inspection, but the previous browser
acceptance suite exercised explicit endpoint actions and missed this expected
workflow. Restore it under [ADR-0027](../adr/0027-two-room-click-routing.md).

## Contract and ordered work

1. Capture Docker Chromium RED for actual room A then room B activation without
   Start here, Directions here or Preview. Preserve the existing artifacts.
2. Default room clicks to choosing route endpoints. First room sets A, a distinct
   connected room sets B and submits once. Later rooms replace B and retain A;
   Clear resets the sequence. Clicking A again only inspects it.
3. Provide a visible Room clicks control with Route A to B (default) and Inspect
   only choices. Inspection mode preserves endpoints and committed directions.
   Search, dropdowns, assistant and explicit room actions retain draft/Preview.
4. Preserve availability guards, exact IDs, submitted snapshots, rejected-room
   inspection, prior routes on failure, and newer navigation ownership. Clear,
   mode changes, explicit edits and newer clicks invalidate waiting selections.
   Room details must not delay routing or restore obsolete inspection.
5. Migrate inspection fixtures to choose that visible mode explicitly. Verify
   default two-click pointer and keyboard/list workflows, cross-floor selection,
   pending availability, unsupported B, Clear and later exploration.
6. Run Docker focused/full package gates, lint, types and artifact QA. Run fresh
   real Chromium/API against accepted artifacts and the running candidate,
   including published port 18107. No source rebuild is needed for a client-only
   change. Record commands, exits, image/container IDs, hashes and fixture scope.
7. Independently review the integrated changes and update HANDOFF, CHANGELOG and
   active navigation instructions. No push, publish or artifact promotion.

The lead owns production, architecture, integration and acceptance. Independent
large-model workers own the new browser regression and existing browser fixture
migration; their files do not overlap. The requested smaller worker model is not
exposed in this session. All execution and evidence processing run in Docker.
