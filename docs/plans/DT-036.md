# DT-036 — Reduce floor loading latency without losing behavior

Date: 2026-11-20
Status: Live verified and independently reviewed; see [evidence](../reports/DT-036.md).

The user reports that restored navigation works but is extremely slow. Recent
live logs show Strand scene requests around 1.1 s and route POSTs around 30–40 ms;
prior larger AQ scenes took several seconds. No test stacks remain and the live
candidate was idle at the first load check. The live app source stays unchanged
while an isolated checkout is measured and repaired.

## First bounded change

1. Record cold/repeated floor API and browser transfer/parse/render timings.
   Benchmark all 11 artifact levels, full response content hashes and geometry
   counts in Docker. Distinguish database scanning from serialization/rendering.
2. Demonstrate a relevant failing regression for scanning unrelated floor rows.
   Push exact level filtering into the read-only OGR query, preserving every
   matching feature, full geometry, field, stable order and error behavior.
   Escape level IDs as SQL string values; no source/index/artifact mutation.
3. Compare all level scene hashes/counts before and after. Verify adversarial
   quoted IDs on a synthetic dataset and normal pointer/keyboard routing.
4. Run a fresh isolated browser/API E2E after this substantial optimization before
   advancing to another change. Keep the default two-click, inspection, Preview,
   failure, Clear and exploration workflows. Do not simplify/hide geometry or
   disable prefetch, controls, data or functionality as a performance shortcut.
5. If measured improvement is insufficient, plan the next separate substantial
   change only after that checkpoint; any cache must be artifact-scoped, bounded,
   thread-safe and preserve responses. No API/schema expansion in this first step.
6. After isolated acceptance, apply the verified code to the live source and
   restart only the app service if required to load Python changes. Run fresh
   final live browser/API performance checks and full Docker package/gates,
   independent review, HANDOFF/CHANGELOG and retained timing/hash evidence.

The lead owns architecture, production integration and the final decision.
Separate workers inspect hotspots, write a bounded regression/benchmark and
review semantic preservation with nonoverlapping ownership. All execution runs
in Docker; isolated source lives inside this repository. The smaller requested
worker tier is not exposed. Raw GDBs/artifacts remain immutable. No push/publish.

## First checkpoint and measured next step

The exact OGR filter passed four meaningful RED→GREEN tests. All 22 complete
scene records (11 floors × two passes) retain identical canonical and wire
hashes, response sizes and feature counts. Scene construction fell from 29.108
to 16.395 seconds in aggregate (43.68%). Fresh-page browser times improved by
18–54%, but the largest AQ floors still take about 1.6 s end to visible.
Fresh two-click and Preview preservation E2E exited 0 before the next code change.
The initially reused private browser IP hit admission limits; successful reruns
used fresh addresses and retained the same assertions and limits.

The complete 11-floor scene bodies total 14,597,469 bytes. If that checkpoint
passes, add an artifact-scoped, thread-safe response-byte cache under ADR-0028,
bounded to 16 scenes / 32 MiB. Keep full response bytes and metadata unchanged.
The normal CLI may prewarm recorded floors before serving, moving one-time
construction cost to startup; prewarming is best-effort and cannot disable
foreground access when a floor fails. Tests cover bounded eviction, concurrent
miss deduplication, errors not cached, artifact isolation and immutable results.
Run the second substantial-change E2E before integration into the live source.

## Verified result

Both substantial changes completed their own preservation E2E before advancing.
All 11 complete HTTP scene bodies and all 16 cold/warm rendered signatures match
baseline exactly. The final isolated suite passed 692 tests with 16 documented
skips and 87.37% coverage; lint, types, artifact QA and launchers passed. After
verified-file integration and a graceful navigation-demo restart, live default
two-click/API E2E passed and eight live fresh-page timings measured 66–267 ms,
86.4–94.4% below baseline. Independent final review approved local delivery.
The isolated checkout is retained as recovery material; test services/networks
were removed. Source data, artifacts, UI workflows and existing tests remain.
