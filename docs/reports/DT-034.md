# DT-034 — Restore the default two-room route workflow

Date: 2026-11-20
Status: Locally verified; independent final review approved

## Incident and repair

The user reported that selecting a room and then another room on
`http://127.0.0.1:18107/` no longer produced directions. The saved checkpoint
was `27f6991` with a clean working tree. Stage C had deliberately converted room
activation into inspection and required separate endpoint and Preview actions.
The previous browser acceptance tests exercised that changed workflow and missed
the user's expected interaction. No lost commit or stopped container caused the
two-click failure.

The new real SVG-pointer regression reproduced the failure before production
edits: after SH1036 then SH3050.1, From and To remained empty and no route POST
was sent. Docker Chromium exited 1 in container `f5c9163174f3`; evidence is under
`build/navigation-review/recovery-two-click-red-20261120/`.

The client now defaults to Route A to B. Map and room-list pointer/keyboard
activation chooses A, then submits a distinct connected B automatically. Later
clicks retain A and replace B; Clear resets endpoints. Inspect only is a visible
alternative that preserves routes. Explicit form/search/assistant actions keep
the submitted-snapshot and Preview contract. ADR-0027 records the amendment.

Room detail requests are independent of routing. A waiting B retains its original
navigation intent and is invalidated by Clear, newer clicks, explicit draft edits
and mode changes. Unsupported B outcomes remain visible beside the map and cannot
submit a doomed request. A newer floor remains displayed after a delayed route
is accepted, with Return to route available.

## Reproduce

From the repository root, the gate image is the explicit local override:

```powershell
docker compose -p sfudt-dt034-gates -f infra/docker-compose.yml -f infra/docker-compose.local.yml run --rm artifact env PYTHONPATH=/workspace/packages/wayfinding/src pytest packages/wayfinding/tests -q -rs
```

Browser commands use the pinned image above, mount `tests/browser` read-only at
`/workspace/tests/browser` and `build/navigation-review` writable at
`/workspace/build/navigation-review`, with a unique `WAYFINDING_BROWSER_RUN_LABEL`.
The published-port rehearsal adds `--add-host demo:host-gateway` and sets
`WAYFINDING_BROWSER_BASE_URL=http://demo:18107` and
`WAYFINDING_BROWSER_PAIR_ONLY=1`. Comprehensive candidate probes instead attach
to `sfudt-sh-navigation-candidate_candidate` and use `http://demo:8080`.
Accepted probes attach to `sfudt-burnaby-asb_browser`, use `http://demo:8080` and
set `WAYFINDING_BROWSER_FIXTURE=accepted`.

The canonical replay used `infra/docker-compose.browser.yml`, project
`sfudt-dt034-canonical`, `WAYFINDING_BROWSER_BUILD_IMAGE=wayfinding-build:local`
and `WAYFINDING_BROWSER_RUN_LABEL=dt034-canonical-final`: `up -d --wait demo`,
`run --rm --no-deps browser`, then `down`. Each command exited 0.
