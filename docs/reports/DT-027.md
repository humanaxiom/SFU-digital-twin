## Changes and RED

`tools/launch-stack.ps1` failed in Windows PowerShell 5.1 before Docker:
`Join-Path : Cannot bind argument to parameter 'Path' because it is an empty string.`
The ComposeFile parameter default used PSScriptRoot before it was populated.
Both start and teardown now resolve an omitted path in their script bodies;
explicit arguments retain their existing meaning. There is no root-level launcher.
The README documents `tools/launch-stack.ps1 -LocalImage` and a separate explicit
Docker image build. The published digest and source masks remain unchanged.

Docker regression RED: two parameter-default guards failed before implementation
(exit 1). After implementation, both pass (exit 0). These are structural guards;
actual Windows behavior is established by the launcher invocations below.

The POSIX launcher gate initially failed with `set: Illegal option -` because its
worktree had CRLF line endings (exit 1). Three shell files were normalized to LF
without content changes; .gitattributes preserves their executable line endings.
The first browser run also failed (exit 1): demo.cjs waited for a route POST after
clicking a disconnected room. DT-024 N15 / ADR-0017 now require that room disabled
without a POST. The assertion was migrated to that accepted contract, preserving
direct unsupported-route API coverage. A second run also failed (exit 1) in the
old actionableOrigin helper, which tried another blocked pair and implicitly
replaced A. That helper now uses explicit Clear under N16; unsupported elevator
failure coverage uses a separate real HTTP API request. The gate does not claim
UI failure-card or UI failure-disclosure rendering coverage. No application code
changed. The third run failed (exit 1) because removing the old setup route also
removed its implicit profile reset; actionableOrigin now explicitly selects its
intended default profile. Failed intermediate evidence remains in the original,
final and final3 labels; the final assembled run uses the final4 label below.
