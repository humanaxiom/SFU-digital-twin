## Implementation

`infra/docker-compose.candidate.yml` adds a digest-pinned nginx service. It runs
as UID/GID 101 with a read-only root filesystem, tmpfs state, all capabilities
dropped, no-new-privileges, and bounded JSON logs. It accepts only `sfuai.ca`,
rejects the default virtual host with nginx status 444, forwards a fixed `Host:
demo`, and clears forwarding identity headers. Its access log omits query strings,
bodies, and headers.

The edge joins the candidate network to reach the backend and the non-internal
bridge required for an active Windows Docker host-port binding. The backend keeps
its loopback-only publication and strict Host allowlist.

## Operations and rollback

The ignored runtime environment sets `WAYFINDING_EXTERNAL_BIND_ADDRESS=0.0.0.0`
and `WAYFINDING_EXTERNAL_PORT=8007`. Recreate the `external` service with the
candidate Compose file to apply its edge configuration. Stop or remove only that
service to withdraw public access; the backend, port 18007, artifacts, and graph are
unchanged.

All external clients share the backend rate-limit bucket because forwarding identity
is deliberately cleared. There is no TLS or authentication. Accounts, credentials,
private source data, and write operations must not be added behind this exception;
a persistent or sensitive service requires the established authenticated TLS ingress.
