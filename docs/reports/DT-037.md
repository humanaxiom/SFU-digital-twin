# DT-037 — Bounded recovery for a stalled floor request

Date: 2026-11-20
Status: Live network/body recovery verified and independently reviewed; original tab cause unconfirmed

## Reported state and evidence limits

The user reported a long floor switch at `http://127.0.0.1:18107/`. The screenshot
selects AQ 6000 while displaying AQ 3000, with starting room AQ3024.1 and a
Loading AQ 6000 message. Its mode/help controls occupy their earlier positions;
the currently served HTML places those controls elsewhere. This supports an
older loaded document, not a confirmed JavaScript revision or network cause.
The screenshot capture time and actual pending request were not collected.

Server access logs redact the level ID and log HTTP 200 after preparing headers,
before writing the body. A logged 0.4 ms scene response does not prove complete
body delivery or browser `response.text()` completion. Earlier DT-036 browser
timings measured fresh clients through completed rendering; they did not test
an already-open tab carrying a permanently pending request. That distinction
was missing from the initial performance conclusion.

## What changed and what is reproduced

`628c3c2` introduced the artifact-scoped client scene/in-flight cache during
Stage D. An unresolved request stays in `loadingScenes`; choosing that floor
again reuses the same promise rather than issuing another GET. The generic
fetch/body read has no application deadline, and `loadScene()` exposes Retry
only when the promise rejects. An indefinitely pending response therefore keeps
Loading visible and Retry hidden indefinitely.

DT-036 optimized server-side floor construction/caching and restarted the backend
to load its tested Python changes. It did not change this client switch code.
An existing browser document and its pending promises survive independently of
server source updates. A request interrupted across a server/network transition
is a possible trigger, not an established cause of the user's screenshot.

Fresh Docker Chromium replayed the exact AQ 3000 → AQ3024.1 → AQ 6000 sequence:
318 ms at `/` and 279 ms at `/index.html`, with all 263 destination-floor rooms
and the selected origin preserved. The later final run measured 397/365 ms.
These observations establish the tested fresh-page behavior, not recovery of the
user's retained tab. The user was asked to compare a fresh `/index.html` document;
no answer was used as evidence of resolution.

Meaningful isolated RED held a real AQ 6000 response's body promise indefinitely.
After 12,611 ms, AQ 3000 remained displayed, the map was busy, Retry stayed
hidden, the origin remained AQ3024.1 and repeat floor activation still used only
one GET. Browser container `2514cbae7823` exited 1. The injected stall proves the
recovery defect while leaving the original transport diagnosis open.

## Bounded fix and preservation

In the isolated checkout `build/experiments/dt037-source` (base `8dd77e6`),
`fetchFloorScene()` now races its complete request/body promise against a
10-second deadline and owns an AbortController. Success still validates exact
floor/artifact identity. A timeout rejects the raced promise, clears the existing
in-flight entry through its existing finally path, and reaches the existing
error/Retry UI. Retry therefore starts a fresh request instead of reusing the
stalled promise.

A late ignored-abort transport completion cannot settle the already rejected
race or populate its scene cache. Existing scene-generation checks preserve
newer navigation. The loaded-scene cache, in-flight deduplication during normal
loads, prefetch, full geometry, camera, endpoints and committed route remain.
No backend/cache/data/API/layout change is part of DT-037.

This bounds stalled asynchronous headers/body delivery. It cannot preempt
synchronous JSON parsing/rendering, force a timer to fire while a browser is
suspended, or retroactively patch JavaScript already loaded in an old tab.
A new document load is required to receive the current client.

VM test harnesses now receive standard browser AbortController and timer globals.
Their Node timers are unreferenced so deliberately unresolved fixtures do not
keep the test process alive. Existing assertions were retained. Three fake-clock
unit cases cover headers timeout/retry, body timeout/retry and late-body cache/
newer-floor ownership; the browser tests use actual elapsed deadlines.
