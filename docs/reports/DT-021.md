# DT-021 — Route overview and map zoom

Date: 2026-09-11. Status: local camera fix verified end to end.

The user's AQ303 → AQ3149 screenshot identifies a camera defect, not a missing
route: the API returns roughly 224 m, but initial selection fits only the departure
marker in a 16 m square. Browser page zoom cannot change the SVG viewBox.
Earlier exact-path tests did not assert screen-space visibility and missed this.

The new real-browser regression reproduced the same failure against the current
port-18087 demo, exit **1**, in `build/takeover-browser/dt021-red/results.json`.
Its screenshot matches the reported tightly cropped starting-room view. The new
assertion requires all current-floor route vertices to lie inside the painted SVG
viewport with margins. Final coverage also checks the full rendered marker-circle
bounds, including a stroke margin, rather than only their centers.

Implementation follows ADR-0014: initial route overview, context for point-only
instructions, explicit map Zoom in/out and route/floor resets. Walking-step
highlighting and native geometry remain unchanged. Zoom is independent of page
zoom and does not intercept page scrolling. Same-floor redraw retains manual
camera; actual floor changes establish a frame for the new floor.

Point-only instructions on floors with only coincident landing markers, including
an express elevator stop, fall back to the floor extent. A 16px minimum screen
margin protects endpoint symbols on long mobile routes. The actual-client harness
now covers 20 guidance behaviors; all three client Python wrappers passed after
these fixes. Additional RED cases captured marker clipping and the degenerate
8m landing view before their fixes.

identified the coincident-landing edge case. It is not final acceptance evidence.
The final source is tested in `dt021-live-final02`, against the existing running
