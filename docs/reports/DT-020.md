# DT-020 — Route choices and visible failures

Date: 2026-09-11. Status: local application workflow verified end to end.

The current demo on port 18087 logged repeated HTTP 409 route requests, while all
four canonical route fixtures still returned 200 from that same running service.
Both selectors offered 1,017 rooms without indicating graph connectivity. Most
arbitrary pairs are unsupported by the accepted graph. The user's exact pair,
profile and URL were requested but have not been supplied.

Older running demos on ports 18077 and 18097 also returned routes without the
structured `guidance` field required by the current bind-mounted frontend. This
is a separate compatibility failure; their existence does not establish which
demo the user was using.

## Changes

- Add read-only, directed, profile-specific route availability under ADR-0013.
  One graph traversal classifies destinations; actual route calculation remains
  authoritative and unchanged.
- Group destination choices into mapped routes, shared route points with no
  walking path, disconnected destinations and unavailable endpoints. Preserve
  selections and the complete room catalog, including the starting room needed
  by native-select Swap and assistant flows.
- Keep pending and failure messages beside the map. An old server response now
  explicitly requests a demo update instead of silently failing to display directions.
- Guard availability requests against stale origin/profile responses and Clear.
  Failure to load choices still permits manual route requests.

Only the existing port-18087 demo was refreshed. No source, accepted graph,
canonical route fields or artifacts were changed. This is a discoverability and
error-display fix, not a repair of disconnected indoor data. DT-017 remains open.
