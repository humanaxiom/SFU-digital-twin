# DT-038 — Retained-tab navigation code update safeguards

Date: 2026-11-20
Status: Locally verified through port 18107; independently approved for delivery

## User confirmation and bounded purpose

After DT-037 the user explicitly confirmed the fresh `/index.html` document was
working and supplied a screenshot showing AQ 6000 with 263 rooms. This establishes
that fresh-document observation; it does not establish why the original retained
tab's transport stalled. The user then authorized continued iteration and selected
update/recovery safeguards.

Previously a tab could retain old JavaScript indefinitely while health reported
unchanged map-artifact hashes. Those hashes identify data, not loaded code. This
iteration adds a code identity check; it never reloads or replaces a working tab.
[ADR-0029](../adr/0029-loaded-client-update-notice.md) records the additive API and
served-script contract. Work took place in `build/experiments/dt038-source`, based
on `6f75750`, while the source-bound live app stayed at its verified baseline.

## Behavior and limits

The server reads raw app.js once per script request, hashes those exact bytes,
and appends a safe newline/semicolon identity hook. The strict directive and
original program remain intact. GET `/demo/v1/client` dynamically reports the
current raw script hash, even after source-bind updates without a Python restart.
Its protocol is version 1. Existing health, data endpoints, static URL forms,
security headers and request admission retain their contracts.

The loaded hook supplies the comparison identity. The first metadata fetch can
never silently become the loaded baseline. Initial, manual and visible-return
checks coalesce into one request and bound headers AND body completion to five
seconds. Automatic return checks are throttled to once per minute; there is no
polling timer. Failed or unrecognized checks stay unknown. Once a different
identity is observed, that fact stays visible through failures or server rollback;
hash order does not establish which version is newer.

The notice preserves the existing document, route, endpoints, floor, selected
instruction, inspected room, zoom and cache. A user-operated noopener link opens
`/index.html` in a separate fresh tab; the original tab keeps its route. The page
explains that the new tab starts fresh. Check for app updates is under Data and
limitations, and the mismatch notice is outside the collapsed details.

This first safeguard detects **app.js navigation code changes only**. HTML/CSS-only
changes require a fresh document. Tabs loaded before this checker existed require
one fresh load to acquire it. It cannot run during browser suspension or preempt
synchronous work. It is consistency detection, not release authentication, source
correctness, route-access verification or physical LAN acceptance.
